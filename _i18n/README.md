# Сборка языковых версий

Русская версия — источник. Остальные языки генерируются из неё.

    src/                  русские страницы — источник сборки
    dict/<lang>.json      словарь «русская строка → перевод»
    dict/_source_ru.json  индекс строк (номер → русская строка)
    tools/extract.py      извлечение переводимых строк из HTML и из JS
    tools/build.py        генерация страниц
    tools/build_tr.py     сборка словаря из TSV-файлов «номер<TAB>перевод»
    tools/sitemap.py      генерация sitemap.xml и robots.txt в корне

## Пересобрать всё

    export SP=$(pwd)/_i18n
    for L in ru en de es cs sk ro hu; do python3 _i18n/tools/build.py $L; done
    python3 _i18n/tools/sitemap.py

Запускать из корня репозитория. Сборка идемпотентна: всегда читает из `src/`,
повторный запуск не задваивает canonical и hreflang.

## Что делает сборка

- подставляет переводы в текст разметки и в строковые литералы JS
  (в тестах весь контент лежит внутри скриптов);
- добавляет языковой префикс внутренним ссылкам, кроме `/legal/` и `/assets/`;
- проставляет `canonical` и `hreflang` на все восемь версий и `x-default`;
- заменяет переключатель языков на список из восьми рабочих ссылок,
  а на страницах тестов, где его нет в исходнике, добавляет вместе со стилями;
- выносит `<style>` в `/assets/css/<hash>.css` и скрипт переключателя
  в `/assets/js/lang.js`, дедуплицируя по содержимому: одинаковые наборы
  стилей шарятся между страницами и между языками.

`assets/` — результат сборки, руками не редактируется.

## Добавить язык

1. Перевести строки из `dict/_source_ru.json` в `dict/<lang>.json`.
2. Добавить язык в `LANGS` и `SEL` в `tools/build.py`.
3. Пересобрать все языки — переключатель и hreflang обновятся везде.

## Границы

- Раздел `legal/` в сборку не входит: документы публикуются только
  на английском и лежат в корне. Ссылки на них языкового префикса не получают.
- Правки контента вносятся в `src/`, затем пересборка. Прямые правки
  в сгенерированных папках теряются при следующей сборке.
